# 运动：让东西动得有重量

渲染做得再真，动得像玩具，它就是玩具。这一份讲运动怎么写、怎么验收，底子是迪士尼的动画十二法则，以及 John Lasseter 1987 年把它们搬到 3D 的那篇论文。

第一版 skill 没有这一份。结果是一列蒸汽火车做出来以后，后面车厢的轮子「看着没动」：转角是算了的，但轮子是没有辐条的实心圆盘，转不转看不出来。

## 先定的规矩

1. **场景单位用米，时间用秒，重力用 9.81。** 速度、加速度、周期都按真实的量填，不凭感觉。
2. **一条主函数。** 主体沿路径走了多远，写成一个函数 `X(t)`。轮子转多少、车体怎么俯仰、烟从哪冒出来，全部从它派生，不各写各的。
3. **会动的东西，要有让人看出它在动的记号。** 转的东西要有不对称的特征，直线走的东西旁边要有不动的参照。
4. **刚体不变形。** 重量靠起步慢、悬挂下沉、车身俯仰和运动模糊来表现，不靠缩放。

## 共用的几个函数

```glsl
float sat(float x){ return clamp(x, 0., 1.); }
float ease (float u){ u = sat(u); return u*u*(3. - 2.*u); }                // 两头速度为 0
float ease5(float u){ u = sat(u); return u*u*u*(u*(6.*u - 15.) + 10.); }   // 两头加速度也为 0

// 从静止平滑加速到「每秒 1 个单位」，用时 T，返回走过的路程。峰值加速度是 1.5 / T
float runUp(float t, float T){ return t <= 0. ? 0. : t >= T ? t - .5*T : t*t*t*(1. - .5*t/T)/(T*T); }

// 弹簧对「突然来一下」的响应，从 0 走到 1。w = 2π × 频率，z 是阻尼比
float stepResp(float t, float w, float z){
  if (t <= 0.) return 0.;
  if (z >= 1.) return 1. - exp(-w*t) * (1. + w*t);                         // 不过冲
  float wd = w * sqrt(1. - z*z);
  return 1. - exp(-z*w*t) * (cos(wd*t) + z*w/wd * sin(wd*t)); }            // 过冲一次再回来
```

- 位置是速度的积分。**不要把位置写成 `smoothstep(0., T, t) * t`**，那样物体会先冲过头再突然慢下来。起步用 `X = V * runUp(t, T)`。
- `stepResp` 的阻尼比取 0.3 到 0.5，会有一次看得见的过冲，一个多周期停稳。来回晃三四次就像果冻。

## 十二法则，落到 `render(t)` 上

必须做的七条，每条都能在拼图或数字上验收。

| 法则 | 在这里怎么做 | 怎么算通过 |
|---|---|---|
| 缓入缓出、节奏 | 起步和刹停用 `runUp`，峰值加速度按真实量级定 | 频闪图上间距有变化；报告里写出峰值加速度 |
| 节奏（尺度） | 会落、会摆、会涌的东西，用米和 9.81 算周期和速度 | 报告里列出周期和落地时间 |
| 次要动作、呈现 | 每个转动件的转角 = 路程 ÷ 半径，并且有辐条、连杆、配重、气门嘴这类不对称的记号 | 间隔八分之一圈的 4 帧里，每个轮子都读得出在转 |
| 跟随与重叠 | 至少两层：主体对加速度的弹簧响应（俯仰、回弹），加一样拖在后面的东西（烟、汽、扬起的雪、挂件） | 停住之后 0.8 秒内取 8 帧，这 8 帧不能一模一样 |
| 挤压与拉伸 | 刚体不缩放；换成悬挂压缩、车身俯仰、运动模糊的拉长 | 任何刚体的长宽比逐帧不变 |
| 呈现 | 同一时间只有一个主动作；平涂级的小图就读得出谁在动、往哪动 | 160 像素宽的平涂帧里看得懂 |
| 弧线 | 路径和「走到哪了」分开写；朝向跟着路径的切线 | 频闪图上轨迹光滑，车身不横着滑 |

另外五条按需要用。

- **预备动作**：有生命的东西（鸟起飞前下蹲）要做。机械只做因果上先发生的事：先放汽、先亮灯、先打舵。
- **夸张**：留一个总系数，默认 1.0，写实画面最多 1.5。
- **扎实的造型**：棱角要倒角，同样的东西每个略有不同。这属于建模和贴图，在那两级验收。
- **吸引力**：全开之后挑毛病时多问一句「这一帧最想看哪里」。
- **两种画法**（一张张画下去，或先定关键姿势）：就是契约本身。运动要么是 t 的闭式函数，要么在加载时模拟一遍存表。

## 尺度感是从重力来的

东西落得多快，只跟重力有关：四分之一秒落 30 厘米，半秒落 1.2 米，1 秒落将近 5 米。观众对这个节奏很熟。

拍微缩模型有一条经验公式：拍 1/k 比例的模型，帧率取 24 × √k，放出来才像实物。反过来说，**画面里靠重力的运动如果比真实快了 √k 倍，观众就会把整个场景认成 1/k 大小的模型。**

```js
const G = 9.81;                                              // 单位必须是米和秒
const fallY   = (t, y0) => y0 - 0.5 * G * t * t;             // 1 秒落 4.9 米
const pendT   = L => 2 * Math.PI * Math.sqrt(L / G);         // 1 米长的挂灯，摆一个来回 2.0 秒
const waveSpd = lam => Math.sqrt(G * lam / (2 * Math.PI));   // 波长 10 米的深水浪，每秒走 3.9 米
const startT  = (V, aPeak) => 1.5 * V / aPeak;               // 配 runUp：起步要用多久
```

所以画面里要留一样靠重力的东西当「尺子」：扬起又落下的雪粉、摆动的挂灯、浪、飘落的叶子。一样都没有，观众就没有判断大小的证据。

大的东西动得慢。大团的烟翻卷一圈要好几秒，大树摆得慢、小枝抖得快，大鸟扇翅慢、小鸟扇得快。

## 跟随：四种写法

**一、延迟。** 子部件就是「一小会儿之前的父部件」。适合周期运动和成串的东西。重的延迟长、停得慢，轻的延迟短、停得快，不要都用同一个延迟。

```glsl
float sway(float t, float i){ return A0 * pow(1.8, i) * sin(W_WIND * t - 0.6 * i); }   // 越往树梢，摆得越大、越晚
float wingTip(float t){ return wingRoot(t - 0.08); }                                  // 翼尖比翼根晚
```

**二、把加速度写成几次台阶。** 弹簧是线性的，响应可以相加，所以这是精确解。车停住的那一刻减速度突然归零，车头会弹回来、过头、再落下，这个细节是自动出来的。

```js
const EV = [[1, +0.4], [6, -0.4], [9, -0.8], [11.5, +0.8]];        // [时刻, 加速度变化了多少]，要配平
const X     = t => EV.reduce((s, [ti, da]) => s + 0.5 * da * Math.max(t - ti, 0) ** 2, 0);
const pitch = t => -KP * EV.reduce((s, [ti, da]) => s + da * stepResp(t - ti, W, Z), 0);
```

**三、加载时积分一次，存表。** 驱动信号是任意平滑曲线时用。步长固定，每次加载结果都一样。

```js
const DT = 1 / 480, N = Math.ceil(DUR / DT) + 2, tab = new Float32Array(N);
for (let i = 0, th = 0, om = 0; i < N; i++) { tab[i] = th;
  om += (W * W * (-KP * acc(i * DT) - th) - 2 * Z * W * om) * DT;  th += om * DT; }
```

**四、排放出去的东西按出生时刻留在原地。** 烟、汽、扬起的雪、船的尾迹。每一团记住自己出生时发射口在哪，之后不再跟着车走，拖尾就自动有了。

```glsl
vec3 puffPos(float k, float t){                       // 第 k 团
  float tb = k / RATE, age = t - tb;                  // RATE：每秒几团
  vec3 p = chimney(tb);                               // 出生那一刻烟囱在世界里的位置
  p.y += V0 / KD * (1. - exp(-KD * age));             // 向上的初速，被空气拖慢
  return p + WIND * age; }                            // 半径随 age 变大，浓度随 age 变淡
```

运动模糊让每个采样的时刻都不同，所以这些函数必须能在着色器里按任意 `t` 求值。函数直接写在 GLSL 里；或者只在 JavaScript 里写，加载时烘成一维浮点贴图，着色器按 `t` 查。

## 三样验收办法

模型看不了视频。运动要么变成一张图，要么变成数字。

1. **频闪图。** 镜头固定，把主体在 6 个等间隔时刻的样子叠在同一帧里（给页面加 `?ghost=1`）。间距均匀说明是匀速，起步和停下的地方间距应该变密。

```glsl
float mapGhost(vec3 p, float t){ float d = 1e9;
  for (int i = 0; i < 6; i++) d = min(d, mapHero(p, t - float(i) * 0.25));
  return d; }
```

2. **曲线图。** 把位置、速度、加速度、俯仰画成一张图再看。看曲线比看逐帧拼图可靠。
3. **数值检查。** 不渲染，直接采样运动函数，把结果写进报告的「量过的」一栏：峰值加速度、各个摆的周期、落地时间、轮子每秒转几圈、轮缘速度和车速差多少（差了就是在打滑）。

另外两张专门的拼图：

- **转动件**：间隔八分之一圈取 4 帧，放大到走行部看，每一个轮子都要读得出在转。
- **停住之后**：从停住那一刻起每 0.1 秒一帧取 8 帧，车体应该回弹过头一次，挂件还在摆，烟还在走。

## 出处

- John Lasseter，《Principles of Traditional Animation Applied to 3D Computer Animation》，SIGGRAPH 1987。「节奏比别的任何一条都更能决定重量」「拖多远、停多久跟重量成正比」出自这篇。
- Frank Thomas、Ollie Johnston，《The Illusion of Life: Disney Animation》，1981。十二法则的原始出处；这里用的是二手转述，没有读到原书。
- Inigo Quilez，《smoothstep integral》。`runUp` 和「位置是速度的积分」。
- Daniel Holden，《Spring-It-On: The Game Developer's Spring-Roll-Call》。弹簧的闭式解。
- Alejandro Garcia，《Physics in Animation: Timing, Spacing, and Scale》。落体的节奏和尺度感。
- Cinematography Mailing List，《Miniature Formula》。微缩模型的帧率公式。
- 阻尼比、车身俯仰的角度、烟翻卷的快慢，没有找到可靠的数值出处，文中给的是推断，以渲出来的效果为准。
