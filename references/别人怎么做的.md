# 别人怎么做的

第二版动手之前，读了十来个公开的 skill、制作手册和提示词。这一份记它们各自最值得学的一点，以及别人给 Fable 5.2 的提示词是怎么写的。都是 2026-11-16 读的；星数、模型、花费是对方仓库里的说法，没有另外核实。

只读了它们的文档和源码，没有运行里面的脚本。下面是转述，不是原文。

## 别人给 Fable 5.2 的提示词是怎么写的

看了十二个画面最写实、最有电影感的公开作品，其中六个找得到提示词原文（凝视的教堂、雨夜码头材质页、千峰之龙、KAGAMI、THE BIG ONE、MiaAI-Lab 的单文件 HTML 合集）。

**共同的结构**

1. 第一句同时说三件事：做什么、交什么文件、不许用什么。
2. 硬约束很少，而且是边界（素材、交付形态、时长），不是做法。几乎没有人告诉 Fable 该用什么算法。
3. 要什么，用名词点名，不用形容词：烛光阴影、空气里的光散射、彩色玻璃；三种尺度的颜色变化、法线起伏、缝隙变暗、边缘磨损。
4. 「不许像什么」单独成段，写的是具体的失败样子，比如「上一版失败的三点」。
5. 结尾是自检加停止条件，再加一句「别问我，自己定」。
6. 长的提示词都点名了一个高光时刻。

**它们几乎都不写的**：镜头焦距、光圈、景深；真实尺寸；运动速度；会转会动的零件怎么做；倒角和小尺度细节。

这张「不写」的清单，正好是那列蒸汽火车出问题的清单。

## 用 Opus 5.5 时要多写什么

唯一一条写明给 Opus 5.5 用的提示词（[makerjackie/the-big-one](https://github.com/makerjackie/the-big-one) 的 `docs/PROMPT.md`），比给 Fable 的多写了三类东西：渲染管线逐步写出来，建模方法写出来，检查脚本点名要写。它的复盘说第一版出来以后「建模太粗糙」，整套重建了。

别人晒的对比（对方自述）：复杂的 3D 场景，Fable 一次通过，Opus 试了三次；同一条提示词，Fable 自己返工得更深，花的钱也多得多。

由此得出的判断：Fable 会自己补上没说的东西，并且自己多看几轮；Opus 对没说的东西取最省事的默认值（一个盒子、一个圆盘、一个顺手的光圈数），检查也只做到要求的程度。所以给 Opus 的提示词要做两件事：

- 把「没说的」写成数字。这就是 `SKILL.md` 里「必须控制的」那张表。
- 把「多看几轮」写成必须交的东西：灰模图、转动件连拍、镜头的数、三轮最弱三处。

这个判断的样本很小：一条提示词、一份复盘、几条自述的对比，加上自己的一次实测。

## 没核实的

- 各仓库写的模型、用时、花费都是对方自述。
- 写实作品里，room-at-dawn、clearwater、crimson-loong 没有找到完整的提示词，它们的约束是从源码里读出来的。
- 「必须控制的」里的数字（倒角半径、部件数、返工轮数）是从别人的手册里借来的起点，要以渲出来的效果为准。
