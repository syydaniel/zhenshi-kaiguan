# 契约和自检

## 为什么要「画面只跟着时间走」

渲染脚本做的事只有一件：第 i 帧永远调用 `render(i / fps)`，然后截图。所以：

- 同一帧不管什么时候渲、渲多少次，结果必须一样。这样才能分块渲、并行渲、断了接着渲，重渲某一段也不会和前后接不上。
- 机器快慢不影响成片。一帧算 10 秒也没关系。

自测办法：隔着别的帧把同一个时刻渲两次，两张截图应该逐字节相同（带颗粒时颗粒的种子用帧号，所以也相同）。

```bash
node render.mjs --page index.html --size 640x360 --q "level=7&ns=8&label=0" --sheet 2,5,2 --cols 3 --out check/det.jpg
for x in 0 640 1280; do ffmpeg -loglevel error -i check/det.jpg -vf crop=640:360:$x:0 -f rawvideo -pix_fmt rgb24 - | md5; done
```

第一条命令在同一个浏览器里依次渲第 2 秒、第 5 秒、第 2 秒，拼成一张图。第二条把三格分别裁出来算校验值（Linux 上把 `md5` 换成 `md5sum`）。第 1 格和第 3 格的校验值应该相同，第 2 格不同。
这样比的是拼图里的像素（截图先存成 JPEG 再拼），不是原始截图；两次渲染只要有一个像素不同，校验值就会不同，所以够用。

## 拼图自检

模型看不了视频，只能看静帧。所以每一步都渲一张拼图再打开看。

1. **逐级对比**：同一时刻，每个级别一帧。`sh sheet.sh index.html check/levels.jpg 2 8 0 1 2 3 4 5 6 7`
2. **时间上的检查**：全开的级别，取镜头的第一帧、最后一帧和中间几帧；快速运动的地方每 0.1 秒取一帧，看运动读不读得出来。`node render.mjs --page index.html --q "level=7&ns=12" --sheet 0.5,1,1.5,2,2.5,3 --cols 3 --out check/time.jpg`
3. **全尺寸看细节**：拼图里每格默认只有 640 像素宽，材质和噪点要渲一张 1080p 的单帧看：`node render.mjs --page index.html --size 1920x1080 --q "level=7&ns=16&label=0" --sheet 2 --cols 1 --w 1920 --out check/full.jpg`。
4. **着色器编译不过**：`sheet.sh` 会把报错打出来；也可以单独跑一次 `node render.mjs --page 页面 --sheet 1 --out check/x.jpg` 看报错里的行号。

每一轮写下**最弱的三处**，改掉，再渲。至少三轮。常见的三类问题：

- 又暗又浑：曝光不够、雾太浓、环境光太弱。
- 像卡通：平涂、圆滚滚、颜色均匀、没有法线起伏。
- 细节不够：大片空而光滑的区域。

不要给自己的画面打分（「8 分」找不出任何要改的东西）。写具体的差距。

有参考图时，把自己的帧和参考图并排打开，比轮廓、材质、密度、光四项。

## 报告怎么写

做完之后分三类说清楚：

- **量过的**：分辨率、帧数、每帧耗时、同一帧渲两次是否一致。
- **只是看过的**：哪几张拼图、看的是哪些时刻。
- **检查不了的**：连续运动的手感、声音、在别的显卡上会不会变慢或者出错。
