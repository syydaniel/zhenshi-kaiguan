# 踩过的坑

都是做三个示例、两条视频，以及让 Opus 5.5 按第一版 skill 做一列蒸汽火车时真实遇到的。

| 现象 | 原因 | 解法 |
|---|---|---|
| 画面大部分是黑的，只有零星几个方块有内容 | 单次绘制太久，被显卡中断 | 把画面切成小块画，每块画完 `gl.finish()`。`harness.js` 里的 `TILES`、`TX` |
| 截图是空的 | WebGL 默认画完就清缓冲 | 取上下文时带 `preserveDrawingBuffer: true` |
| 地形或贴图上有规则的条纹 | `fract(sin(...))` 哈希在大坐标下精度不够 | 格点哈希改用整数运算 |
| 山坡上一格一格的台阶 | 高度图分辨率不够，法线取样间距小于一个纹素 | 法线的取样间距不小于一个纹素；高度图用 4096 |
| 表面全是黑斑 | 阴影光线从表面上起步，打中自己 | 起点沿法线抬一点 |
| 第一版室外场景发白、没对比 | 雾太浓，雾色太亮 | 密度先减半；色调映射后再加对比 |
| 主体太小、太远 | 按「真实比例」摆的，没按画面摆 | 先定主体在画面里占多大，再反推距离和焦距 |
| 街道全在影子里 | 太阳低，两边的楼把光挡完了 | 让太阳顺着街道的方向照，或者在楼之间留空 |
| 重的场景 1080p 一帧十几秒 | 每一步都在算整个场景 | 给远处的东西算一个便宜的下界，离得远就跳过；光柱的遮挡测试用粗略版场景；采样数按级别降 |
| 往场景里贴的字，深色底板压不住后面的内容 | 发光的贴图只能加亮，不能变暗 | 让后面的内容自己变淡，不要盖深色板 |
| 贴进场景的字在景深打开后看不清 | 字不在焦平面上 | 把字放在焦点附近，或者那一段把光圈收小 |
| 运动的球上，贴图在表面滑动 | 噪声用的是世界坐标 | 先变换到物体自己的坐标系 |
| 无头 Chrome 很慢 | 没用上真显卡 | macOS 加 `--use-angle=metal --enable-gpu --ignore-gpu-blocklist`，Windows 换成 `--use-angle=d3d11` |
| 整个场景像摆在桌上的微缩模型 | 光圈半径照感觉填了 0.04 米（口径 8 厘米），广角镜头里不存在这样的光圈 | 先定镜头（毫米、光圈值），光圈半径由公式算；写之前跑 `node lens.mjs`。见 `镜头.md` |
| 后面车厢的轮子看着没在转 | 轮子是没有辐条的实心圆盘，转角在算，但看不出来 | 会转的东西都要有不对称的记号（辐条、配重、连杆）。见 `运动.md` |
| 近处的电线杆把主体挡了三秒 | 镜头走得慢，杆子在画面正中慢慢挪，又被大光圈虚成一条灰影 | 镜头慢时把前景放到画面最外侧当边框；镜头快时让它在 0.3 秒内划过，并且避开关键时刻。见 `镜头.md` |
| 火车慢得没有分量 | 车速每秒 2.5 米，烟往斜上方飘，环境没有任何反应 | 速度按真实的量写（火车每秒 15 到 25 米）；烟往后躺，卷起雪雾，桥面震动 |
| 推近以后更像玩具 | 棱角没有倒角，颜色纯而均匀，石块纹理偏大，画面里没有能比出大小的东西 | 见 `场景搭建.md` 的「玩具检查」 |
| 4K、采样数调高以后整帧全黑，同时在跑的别的显卡任务也崩了 | 单次绘制太久，显卡把它掐掉了 | 每块的像素数乘采样数不要超过 1080p 时的量：4K 用 `?tiles=72&tx=16`。重的渲染不要和别的显卡任务同时跑 |
| 模型没有一级一级写，一口气写完九级再回头截图 | 文档只说了「不要跳」，没有说为什么，也没有检查点 | 提示词里要求每写完一级就贴出这一级的拼图再往下写 |
| 主体和镜头都对了，画面还是假 | 背景是一块白板：平地上撒着一样的圆锥树，说好的深谷看不出深度 | 环境也要按 `场景搭建.md` 的「环境不能是一块白板」来做；把主体遮住看剩下的像不像一张风景照 |
| 主体比规格表写的小了一截 | 中途把机位放低、退远了，焦距没跟着改 | 主体大小是硬指标，改机位就同时改焦距 |
| 前景的电线从车头上横着切过去 | 只算了电线杆划过的时刻，没管电线在画面里的高度 | 贯穿画面的细线放在主体上方或下方 |
| 按新版流程做，耗时和花费是第一版的三倍多 | 四道闸门、灰模、逐级拼图、三轮返工都要渲图看图；场景也更重，每帧从 7 秒涨到 18 秒 | 这是换来的代价，开工前要知道。想省就少渲检查图的分辨率，或者把灰模和逐级拼图用 640×360 渲 |
