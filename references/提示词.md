# 可以直接发给模型的提示词

把 `kit/` 复制到一个空目录，在里面打开你的编程助手，把下面这段发过去。尖括号里换成你的题材。

```text
用当前目录里的 harness.js 和 render.mjs，新写一个场景页面 scene.html：<一句话写清场景、主体、光从哪来、镜头怎么动、什么东西在动>。时长 8 秒，24 帧每秒。
可以先读 index.html（室内静物）、lake.html（自然环境）、mech.html（城市和机械），挑最接近的一个当底子。

硬性约定：
1. 页面先设 window.SCENE = { FS, NAMES, DUR: 8 }，再加载 harness.js（FS 是片元着色器，NAMES 是每一级的名字，DUR 是时长秒数）。画面必须是时间的纯函数：不用 Date.now()、performance.now()、不带种子的 Math.random()，不保留上一帧的状态。运动写成 t 的闭式函数。
2. 不加载任何外部素材。贴图用噪声现算。
3. 着色器里用 lvl 分级，从 0 到 7 依次是：平涂、直射光和硬阴影、程序化贴图、环境光和反射、软阴影和接触阴影、景深、运动模糊、色调映射和颗粒。室外场景在软阴影后面加一级「空气」，这时一共九级（0 到 8），景深、运动模糊、色调映射的编号各往后挪一位，对照表在 references/开关.md 开头。每一级只在上一级的基础上加东西。

做法：
- 先写 3 行以内的分镜，再写代码。
- 一级一级写。每写完一级，运行 sh sheet.sh scene.html check/lv.jpg 2 6 <到目前为止的级别>，打开 check/lv.jpg 看。这一级的变化要一眼看得出来。
- 每个表面都要有三种尺度的颜色变化、法线起伏、粗糙度变化，缝隙处变暗。不允许大片空而光滑的区域。
- 场景里要有近处的前景（给景深用）和动得快的东西（给运动模糊用）。
- 不要出现这些默认套路：黑底中间飘小物件、满屏发光粒子、紫蓝渐变。

自检（做完再回复我）：
- 全开之后渲一张 1920×1080 的单帧（node render.mjs --page scene.html --size 1920x1080 --q "level=<最高级>&ns=16&label=0" --sheet 2 --cols 1 --w 1920 --out check/full.jpg），写下最弱的三处，改掉，再渲。至少做三轮，每轮只说「改了什么、还差什么」。
- 把同一个时刻隔着别的帧渲两次，确认两张图一样（命令见 references/契约和自检.md）。
- 最后渲出逐级对比的拼图 check/levels.jpg 和一段逐级打开的 out/demo.mp4，报告每帧耗时，并说明哪些是量过的、哪些只是看过、哪些检查不了。
```
